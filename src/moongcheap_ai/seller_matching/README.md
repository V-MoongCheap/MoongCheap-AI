# Seller Matching

Demand Cluster와 Seller Offer를 카테고리·MOQ·가격 세 검사로 비교해 후보(`CANDIDATE`)와 검토 대상(`REVIEW`)으로 나눈다.
세 검사를 **모두** 통과해야 후보다. 순위와 낙찰은 정하지 않는다. 로컬 E2E 데모(`scripts/e2e/run_mvp_local_e2e.py`)의 기준선이다.

## 현재 동작과 한계

| 항목 | 내용 |
|---|---|
| 카테고리 | 수요 `label` 또는 `category_id` 끝부분이 공고 텍스트에 **포함**되는지 본다. 표현이 다른 같은 카테고리는 놓치고, 「홍삼맛 캔디」 처럼 라벨을 포함한 다른 상품은 잡는다 |
| MOQ | 공고에 MOQ 가 없으면 충족으로 세지 않는다 (`moq_known`) |
| 가격 | 유한한 양수 가격이 있어야 한다 |
| 동일 상품 | 공고에 표준 카탈로그 ID 가 없어 확정하지 않는다 (`reason` 의 `exact catalog identity unresolved`) |
| 결측·비유한 입력 방어 | E2E 스크립트는 CSV 를 문자열로 읽고 빈 값을 `""` 로 채우며, 클러스터 수량은 `cluster_demands` 가 1 이상으로 채운다. 그래서 **결측 `nan`·수량 결측은 현재 E2E 경로에서 생기지 않는다** (글자 `nan` 도 빈칸이 된다). 반면 **가격 칸의 `inf`·`Infinity` 글자는 그대로 남아**, 기존 기준선에서는 가격 있음·후보가 됐다 — 현재 경로에서도 생긴다. 실제 데이터의 발생 빈도는 측정하지 않았다 |
| `score` | 참고값이며 판정에 쓰지 않는다. 출력 형식과 정렬을 위해 남긴다 |

## 확인 대기

이 패키지의 구현 방향을 가르는 항목이다. **코드로 정하지 않는다.**

| 항목 | |
|---|---|
| 낙찰 판정 주체 | 「AI-Backend 낙찰 판정 연동 API 기능 요구 명세서」(v0.1 · 2026-09-10) 는 *"낙찰 판정은 AI 가 담당"* 하고 평가 결과 중 **최대 1건을 `isAwarded = true` 로 선정**하라고 한다. 「AI API Contract」 4절 「낙찰 판정」 은 이를 Backend 에 둔다. **더 최근인 전자를 전제로 잡되**, 전자가 스스로를 *"AI 팀, PM 과의 협의를 위한 설계 정리본"* 이라 적으므로 계약을 대체했는지는 확정 대기 |
| ↳ 딸린 충돌 | 낙찰 판정 문서는 `score`(0.0000~1.0000)를 **필수**로 두는데 「평가 / Gold Set 세부 정의」(v0.3) 6-2절 「처리 순서」 는 *"총비용 오름차순 순위화, 동률은 공고 ID로 확정"* 으로 끝나 **순위를 내고 0~1 점수 산식은 두지 않는다.** 상태값 `GB_AWARDING`·`AWARDING`·`LOST` 도 「Status 값 정리」 에 없는 신규 3종이다 |
| ↳ 낙찰 대상 감지 경로 | 같은 문서가 Option A(GET 폴링) / B(뷰 직독) 중 하나를 **AI 팀이 정하라**고 한다. **AI 파트는 A 를 선택했다. 운영 계약 세부는 협의 중이고 연동은 미완료다** — 「AI-Backend 낙찰 대상 조회 API 응답 양식(협의안)」 을 A 기준으로 전달했고, 「AI-Backend 낙찰 판정 연동 API 기능 요구 명세서 응답」 1절이 GET 조회 방식(`size`, offset 없음)으로 답했다. B 는 스키마가 바뀌면 빈 결과로 조용히 실패하고, 그것은 「낙찰 대상이 없다」와 구분되지 않는다 |
| 순위 기준 · 적합도 척도 | **순위를 무엇으로 매길지가 문서마다 다르다.** 「모델 & 실험 계획」(v0.4) 5.4절은 사람이 매긴 *"적합도"* 와 NDCG@K 로 평가한다고 하나 척도·기준·검수 주체를 정의하지 않는다. 같은 문서 7.2절이 지표 세부를 Evaluation Specification 에 넘겼고, 「평가 / Gold Set 세부 정의」(v0.3) 6절은 **총비용 오름차순 순위**와 `expected_rank`·Rank Agreement 로 정해 **척도 없이 평가할 수 있다.** 반면 「모델 & 실험 결과」 10.1절은 Seller Matching 을 *"Structured Rule + Weighted Scoring"* 으로, 낙찰 판정 문서는 0~1 `score` 를 적는다. 총비용 순위로 가면 척도가 필요 없고, 가중 점수로 가면 척도 정의가 다시 필요하다 — **확정 대기** |
| Violation Rate 의 모집단 | 「AI 평가 데이터셋 및 평가 지표 정의서」 11.3절 은 위반 Action / 전체 자동 계획 Action 으로 둔다. Seller Matching 에서는 Offer / Offer 가 맞아 보이나 **제안이며 승인된 정의가 아니다** |
