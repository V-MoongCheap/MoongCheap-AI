# Seller Matching

Demand Cluster와 Seller Offer를 가격, MOQ, 공급수량, Facet 조건으로 비교하고 평가·순위를 생성한다.

## 확인 대기

이 패키지의 구현 방향을 가르는 항목이다. **코드로 정하지 않는다.**

| 항목 | |
|---|---|
| 낙찰 판정 주체 | 「AI-Backend 낙찰 판정 연동 API 기능 요구 명세서」(v0.1 · 2026-09-10) 는 *"낙찰 판정은 AI 가 담당"* 하고 평가 결과 중 **최대 1건을 `isAwarded = true` 로 선정**하라고 한다. 「AI API Contract」 4절 「낙찰 판정」 은 이를 Backend 에 둔다. **더 최근인 전자를 전제로 잡되**, 전자가 스스로를 *"AI 팀, PM 과의 협의를 위한 설계 정리본"* 이라 적으므로 계약을 대체했는지는 확정 대기 |
| ↳ 딸린 충돌 | 낙찰 판정 문서는 `score`(0.0000~1.0000)를 **필수**로 두는데 「T24 게시본」 6절 「순위 산정」 은 *"MVP 에서는 점수를 생성하지 않는다"* 고 한다. 상태값 `GB_AWARDING`·`AWARDING`·`LOST` 도 「Status 값 정리」 에 없는 신규 3종이다 |
| ↳ 낙찰 대상 감지 경로 | 같은 문서가 Option A(GET 폴링) / B(뷰 직독) 중 하나를 **AI 팀이 정하라**고 하며 나머지 항목의 선행 조건이라 적는다. **A 를 권한다** — B 는 스키마가 바뀌면 빈 결과로 조용히 실패하고, 그것은 「낙찰 대상이 없다」와 구분되지 않는다 |
| 적합도 척도·검수자 | 「모델 & 실험 계획」 5.4절이 *"적합도"* 라는 이름만 적고 **척도·기준·검수 주체·인원을 정의하지 않는다.** 척도가 없으면 Gold Set 에 등급을 매길 수 없고, 등급이 없으면 NDCG@K 를 낼 수 없다 — EXP-008 이 여기서 막힌다 |
| Violation Rate 의 모집단 | 「AI 평가 데이터셋 및 평가 지표 정의서」 11.3절 은 위반 Action / 전체 자동 계획 Action 으로 둔다. Seller Matching 에서는 Offer / Offer 가 맞아 보이나 **제안이며 승인된 정의가 아니다** |
